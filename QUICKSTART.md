# ⚡ Быстрый старт Storra WMS

## Установка и запуск — одна команда

### macOS / Linux
```bash
chmod +x setup.sh
./setup.sh
```

### Windows
Дважды кликните `setup.bat` или в cmd:
```cmd
setup.bat
```

Скрипт сам:
1. Проверит Node.js (нужен 18+, лучше 20 LTS — https://nodejs.org)
2. Поставит зависимости клиента и сервера (`npm install` x2)
3. Сгенерирует `server/.env` с уникальным криптостойким `JWT_SECRET`
4. Соберёт фронт (`npm run build` → `dist/index.html`)
5. Запустит сервер на `http://0.0.0.0:3000`

**Логин по умолчанию:** `admin` / `admin123` — **ОБЯЗАТЕЛЬНО смените после входа** в разделе «Настройки → Пользователи».

## 🔄 Как работает синхронизация между ПК

После этих правок **все данные хранятся на сервере** (SQLite в `server/data/storra.db`). Клиенты с разных ПК подключаются к одному и тому же серверу, и:

1. **Сразу после входа** клиент скачивает с сервера: товары, ячейки, остатки, заказы, акты, настройки.
2. **При любой операции** (создать товар, приёмка, отгрузка, заказ и т.д.) клиент шлёт запрос на сервер, сервер сохраняет в SQLite и **рассылает WebSocket-эвент всем подключённым ПК**.
3. Другие клиенты ловят эвент `product:changed`, `stock:changed`, `order:changed` и т.д. — и **автоматически подкачивают свежие данные** без перезагрузки страницы.

### Что значит «сервер» в вашем сценарии

Сервер — это ваш ПК, на котором запущен `setup.bat`. Другие ПК подключаются к нему по локальной сети (`http://10.162.0.167:3000`).

⚠️ **Если ПК с сервером выключен — другие ПК ничего не видят.** Поэтому:
- Держите сервер на одном «главном» ПК / NAS / мини-ПК склада.
- Регулярно делайте бэкап файла `server/data/storra.db` (или через UI: Настройки → Бэкап БД).
- Если нужна реальная отказоустойчивость — поднимите сервер на отдельной машине, которая всегда включена.

### Что делать, если на одном ПК изменения не появляются

1. **Обновите страницу** (Ctrl+R). Это пересоздаст WebSocket и заново синхронизирует всё.
2. Откройте F12 → Network → ищите подключение `ws://...:3000/api/ws`. Если оно `pending` или `closed` — проверьте, что firewall не блокирует.
3. На windows-сервере правило firewall:
   ```cmd
   netsh advfirewall firewall add rule name="Storra WMS" dir=in action=allow protocol=TCP localport=3000
   ```

### Что синхронизируется

| Раздел | Создание | Изменение | Удаление | Real-time через WS |
|---|---|---|---|---|
| Товары | ✅ | ✅ | ✅ | ✅ |
| Ячейки | ✅ | ✅ | ✅ | ✅ |
| Остатки (Приёмка/Отгрузка/Перемещение) | ✅ | ✅ | ✅ | ✅ |
| Заказы и позиции | ✅ | ✅ | ✅ | ✅ |
| Резервирование (Pick) | ✅ | ✅ | ✅ | ✅ |
| Акты осмотра и переборки | ✅ | ✅ | ✅ | ✅ |
| Настройки | ✅ | ✅ | — | через polling |
| Аналитика ABC/XYZ | ✅ | ✅ | — | ✅ |
| Аудит-лог | ✅ | — | — | — |
| Инвентаризация (сессии) | **локально** | **локально** | **локально** | — |

> Инвентаризационные сессии хранятся локально (это «черновик» для текущего оператора). Когда сессия закрывается, **корректировки применяются на сервер** через стандартные API приёмки/отгрузки, и все ПК их видят.

## Доступ с других ПК в сети

Когда сервер запустится, в консоли будут показаны IP-адреса для подключения:

```
  • На этом ПК:        http://localhost:3000
  • С других ПК в сети: http://192.168.1.42:3000
```

### ⚠️ Если открыли с другого ПК и видите бесконечную загрузку

Это была известная проблема — починена в этой версии. Если всё ещё висит:

1. **Жёстко перезагрузите страницу** (Ctrl+Shift+R / Cmd+Shift+R) — старый Service Worker мог закэшировать сломанную версию.
2. **Очистите кэш сайта** в DevTools (F12 → Application → Storage → Clear site data).
3. Откройте DevTools (F12) → вкладку Console и пришлите ошибки, если они есть.

### Почему PWA / камера могут не работать на `http://192.168.x.x`

Браузеры разрешают `crypto.subtle`, `navigator.mediaDevices` и `serviceWorker` только в **secure context**: HTTPS, `localhost` или `127.0.0.1`.

Само приложение и логин на сервере работают через любой `http://`. А вот **локальная (оффлайн) авторизация в IndexedDB**, камера и установка PWA — только при secure context.

**Решения:**
- Открывайте на самом сервере через `http://localhost:3000` — всё работает.
- Если нужен HTTPS для всех ПК в сети — поставьте reverse-proxy с самоподписанным сертификатом (например, через Caddy за 5 минут) или [mkcert](https://github.com/FiloSottile/mkcert).

## 🆘 Если предыдущая версия `setup.bat` ругалась

В первой версии скрипта была ошибка с экранированием — могло появиться:

```
Непредвиденное появление: ....
```

или нечитаемые символы вроде `╤Г╤Б╤В`. Это исправлено:
- Файл теперь сохранён в **UTF-8 с BOM** (cmd видит русский корректно).
- Добавлен `chcp 65001` для переключения кодировки консоли.
- Генерация JWT-секрета вынесена в `scripts/gen-jwt-secret.js`, чтобы не воевать с кавычками cmd.

Если у вас остался кэш предыдущего запуска — просто перезапустите `setup.bat`, всё должно пройти заново.

## Что куда установилось

| Папка | Что внутри |
|---|---|
| `node_modules/` | Зависимости фронта (React, Vite, Tailwind) |
| `server/node_modules/` | Зависимости сервера (Fastify, SQLite, Drizzle) |
| `dist/` | Собранный фронт (отдаётся сервером и сам открывается из файла) |
| `server/data/storra.db` | База данных SQLite — **бэкапьте её** |
| `server/.env` | Конфиг сервера с `JWT_SECRET` — **не публикуйте** |

|---|---|
| Перезапустить сервер | Ctrl+C в окне, потом снова `./setup.sh` |

## Если что-то сломалось

1. **Снести и поставить заново:**
   ```bash
   rm -rf node_modules server/node_modules dist
   ./setup.sh
   ```
2. **Снести БД (потеряете все данные!):**
   ```bash
   rm -rf server/data
   ./setup.sh
   ```
3. Откройте issue с логами консоли сервера и DevTools браузера.
